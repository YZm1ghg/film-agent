# 知识模块路由与检索指南

> 本卡是**技能自身的知识体系地图**：遇到什么问题该读哪个知识模块、该派哪个子智能体、
> 以及原文检索的引用纪律。
>
> 它**不是**书单。本插件不附带、也不分发任何书籍原文；检索层面向的是
> **用户自己提供/自己构建的影视专业书库**（见 §5）。

## 三、 学习路径（按目标）

设计成两条腿走路：**先读本插件的知识模块建立框架，再去用户自己的书库里补原文细节**。

### 路径 1：零基础 → 看懂电影（4 周）

```
W1: cinematography-language.md 全篇（景别/机位/轴线/运动/构图/剪辑）
W2: scene-analysis.md §1-3（拉片七维度 + 拉片表）
W3: film-history-theory.md §1-2、§5（史与类型坐标）
W4: aesthetics-theory.md §2、§4（视觉心理学 + 母题）＋ 自己拉片 3 个段落
→ 产出：能用 8 个维度分析任意一部电影
```

### 路径 2：零基础 → 能写剧本（6 周）

```
W1: screenwriting.md §1-2（logline、三幕、情节点）——先写完整一稿
W2: screenwriting.md §3-4（人物 Want/Need/Wound、冲突）
W3: screenwriting.md §5（对白与潜台词）
W4: screenwriting.md §6（结构变体：非线性/环形/多线）
W5: practical-sops.md 改稿 SOP ——逐条对照自己的稿子
W6: 派 film-expert ② 剧本诊断（结构/场景/人物/对白四层）
→ 产出：一个完整剧本 + 一轮结构化改写
```

### 路径 3：零基础 → 能拍（6 周）

```
W1: practical-sops.md 短片 SOP（全流程概览）
W2: cinematography-language.md（镜头句法速成）
W3: directing-acting.md §5（故事板六格要素）→ 做自己的分镜
W4: cinematography-lighting.md §2-4（三点布光、光比）→ 布光练习
W5: sound-design.md §8 + practical-sops.md 录音清单 → 现场收音练习
W6: directing-acting.md §2-3（场面调度）→ 拍一个 1 分钟段落
→ 产出：一份分镜 + 一段实拍短片
```

### 路径 4：进阶理论（8 周）

```
W1-2: film-history-theory.md §3（理论三阶段）→ 建立理论框架
W3-4: aesthetics-theory.md §1、§3（本体论 + 符号学）
W5:   knowledge/11-film-history.md（分年代/流派经纬）
W6:   film-history-theory.md §4（批评路径与方法）
W7:   knowledge/13-film-theory.md（理论工具盘点）
W8:   scene-analysis.md §5 → 写一篇 2000 字的分析文章
→ 产出：一篇有理论支撑的影片分析
```

### 路径 5：专项（各 2 周）

```
声音:   sound-design.md 全篇 → 做一段 1 分钟的声音设计
纪录片: documentary.md 全篇 → 写一份纪录片提案
制片:   production-financing.md §2-4 → 一份预算表 + 融资计划
类型:   knowledge/12-genre.md → 拆解 3 部同类型片的演变
```

## 四、 去书库补细节：什么时候该检索

知识模块是**提炼过的操作系统**，够应付日常问答；但下面这些情况必须回到原文：

- 用户要**具体案例、原话、页码**
- 模块里没有的**细分主题**（某位导演、某个年代、某个技术细节）
- 需要**精确表述**（某位理论家的原话、某个术语的原始定义）

方法：派 `film-expert` 子智能体（模式① 检索），它只读、只摘录、只给出处。
用法见 `SKILL.md` §0.5 与 §4。

**注意**：检索层是否可用，取决于用户有没有在自己的书库目录下建好语料
（见 §5）。没有语料时，检索命令会返回空——这时**如实说明"库内未检索到"，
然后给行业通行做法**，不要用模块里的内容假装成原文出处。

## 五、 语料来源与引用纪律

**语料来源**：本插件**不附带任何书籍原文**。检索层面向的是
**用户自己提供、自己合法获得的影视专业书库**。用户把书库目录配置好后，
可以自行用 `corpus/` 里的脚本建立索引与全文检索能力。

**引用纪律（本插件的硬规则）**

1. **页码只能来自真实检索。** 摘录里的每一页都必须是 `search` / `read` 真实返回的。
   **绝不推算页码、绝不编造原文、绝不"大概在第 100 页左右"。**
2. **摘录逐字。** 不改写、不总结、不翻译；原文的 OCR 错字照抄，那不是该修的。
3. **检索不到就说没有。** 措辞用「**库内未检索到**『X』的直接论述」，
   再说明库里有覆盖的邻近主题；不要为凑答案引用不相关内容。
4. **区分"书里怎么说"与"我建议怎么做"。** 前者必须带出处，后者不必，
   但不能把后者包装成前者。
5. **扫描件有错字风险。** 若某本的识别置信度偏低，摘录后加一句
   「该本识别质量较低，引用前宜核对原书」。
6. **引用格式**：`（《书名》第 N 页）` —— 书名 + 页码，便于用户回查自己的书。

**索引定位**：用户书库里的每本书有编号与"书卡"
（`corpus/out/cards/<书名>.md`，含检出章节列表与主题词命中统计）。
判断"这个主题该查哪本"先看书卡，比盲目搜快得多。

## 六、 一句话总结

- **日常创作与问答** → 直接读 `references/` 与 `knowledge/` 的模块，不需要检索。
- **要出处、要案例、要原话** → 派 `film-expert` 检索模式，页码必须真实。
- **查不到** → 说"库内未检索到"，给通行做法，**绝不编造**。
